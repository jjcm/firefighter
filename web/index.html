The process

01

((·)) Listen

The hub polls X and official sources centrally, then broadcasts signed vulnerability notices to every subscriber.

02

⌕ Investigate

Each server’s LLM checks its own versions, exposure, logs, and evidence. A notice is a lead, never a command.

03

⌁ Respond

Apply package or code fixes, test changes, contain exposure, and invoke configured key-rotation hooks.

04

▤ Verify & report

Check the fix and service health. Use rollback when supplied. Keep a local audit and report to Grok Bot.

↳ Shared intelligence. Independent decisions. Remediation runs on your server.

Installation quickstart

A local agent, your model API, and one shared notice feed.

Ubuntu · Linux amd64
curl -fLO https://YOUR_NOTICE_HUB/downloads/firefighter-linux-amd64
curl -fLO https://YOUR_NOTICE_HUB/downloads/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo install -m 0755 firefighter-linux-amd64 /usr/local/bin/firefighter
sudo mkdir -p /etc/firefighter
curl -fLO https://YOUR_NOTICE_HUB/downloads/firefighter.example.json
sudo install -m 0600 firefighter.example.json /etc/firefighter/config.json

For a new installation. Preserve existing configuration when upgrading. For ARM servers, use the arm64 binary. Compare checksums with a trusted release before installing.

/etc/firefighter/config.json · sources
"sources": [{
  "name": "central-notices",
  "type": "broadcast",
  "url": "https://YOUR_NOTICE_HUB/api/v1/notices",
  "public_key": "YOUR_VERIFIED_PUBLIC_KEY",
  "interval_seconds": 15,
  "lookback_hours": 0
}]

Replace the existing sources list to use central intake. Get the hub public key, verify it independently, then pin it here. Clients verify signatures; the browser board displays notices without authenticating them.

System service · your model API
curl -fLO https://YOUR_NOTICE_HUB/downloads/firefighter.service
curl -fLO https://YOUR_NOTICE_HUB/downloads/firefighter.env.example
sudo install -m 0644 firefighter.service /etc/systemd/system/
sudo install -m 0600 firefighter.env.example /etc/firefighter/firefighter.env
sudoedit /etc/firefighter/firefighter.env /etc/firefighter/config.json
sudo systemctl daemon-reload
sudo systemctl enable --now firefighter
sudo journalctl -u firefighter -f

Before starting, set the credential named by llm.api_key_env in the root-only environment file. Choose your compatible API/model and add application paths, health checks, and rotation hooks. This service runs as root without approval prompts.

Operational boundary

Runs as root.
Makes changes.
Keeps an audit trail.

The local LLM decides what to investigate and fix. There are no runtime approval prompts. Commands, results, verification, and recovery attempts are recorded locally.

Relevant local observations are sent to your configured model API. Secret redaction is best effort.

A successful patch does not prove a host was never compromised. Backups, independent monitoring, and recovery from a trusted system still matter.
