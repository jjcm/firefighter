The process

01

((·)) Listen

The hub pulls official vulnerability sources centrally, then broadcasts notices to every client.

02

⌕ Investigate

Each client’s LLM checks its own versions, exposures, logs, and evidence.

03

⌁ Respond

The client’s LLM applies package or code fixes, tests changes, contains exposures, and invokes the configured key rotation hooks.

04

▤ Verify & report

Checks the fix and service health, uses rollback when supplied, and sends a report to an agent of your choice.

>_

Installation quickstart

This might delete your entire server.

This is an experimental, unproven approach. The bet is that a LLM with root access is less of a risk than a slow human. Keep tested, independent backups and read the FAQ.

Install
curl -fsSL https://firefighter.sh | sudo bash

Notice: this runs as a root service and gives an LLM root access.

Operational boundary

Runs as root.
Makes changes.
Keeps an audit trail.

The local LLM decides what to investigate and fix. There are no runtime approval prompts. Commands, results, verification, and recovery attempts are recorded locally.

Relevant local observations are sent to your configured model API. Secret redaction is best effort.

A successful patch does not prove a host was never compromised. Backups, independent monitoring, and recovery from a trusted system still matter.
